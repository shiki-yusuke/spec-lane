## MV-03: `ledger_summary.accounting_bases` / `accounting_basis_status` (RULE-35)

上記 supersede 後の状態に加えて、同じ intent の別 phase (`2_spec`) に
pre-lane entry（PATH の実 `agent-cost` 0.1.0, accounting_basis キーなし）を
temp 側だけで追加し、v2 entry と pre-lane entry が cost_ledger に混在する状態を作った
（`work/active` を phase 2_spec 用の新規 task_run に差し替え、
`@lane/core` の `buildTraceEvent`/`appendTraceEvent` を直接呼んで
正規の `session_bound` イベントを1件追加 -- これは実データではなく、この検証専用の
フィクスチャとして temp 内にのみ作成したもの）。

コマンド:
```
LANE_DATA_DIR=<temp>/data LANE_CONFIG_DIR=<temp>/config \
  node .../main.js evidence export --format lane-evidence:v1 \
  --intent I-2026-08-15-agent-cost-claims-corpus --spec-dir <temp>/spec
```

**結果: 部分的に確認できた。**
- `accounting_basis_status` = `"unqualified"` ―― 確認できた。
- `accounting_bases` = `[]`（空配列）―― 期待していた
  「2要素・辞書順（`["agent-cost-raw-total/v2","unknown"]`のような)・unqualified」
  ではなく、**空集合側の unqualified** だった。

原因: `summarizeLedger`（`packages/core/src/application/evidence-export-service.ts`）は
`accounting_bases` を `included_in_kpi:true` の entry からしか集計しない。今回の
2つの entry はどちらも session が `matched:false`（前述の通り本物の transcript が
この環境に存在しないため）で `included_in_kpi:false` となり、`included` 配列が空
だったため `accounting_bases=[]` になった。コード上のコメント (RULE-35) は
「`"unqualified"` は真の混在と空集合の両方をカバーする」と明記しており、これは
その空集合側のケースを実機で踏んだことになる。真の2要素混在（両方
`included_in_kpi:true`）は、この sandbox 上で実際に `agent-cost` が matched:true を
返す session transcript を見つけられず（複数の候補 session で試したが全て
`matched:false`）、実データ経由では再現できなかった。ユニットテスト
`packages/core/test/basis-gate-services.test.ts:709-753` に3ケース
（single / 2要素混在・辞書順 / 空集合）すべてのテストが既にあることは確認した
（fixture entry を直接構築しており、このユニットテストは e2e の CLI 経由ではない）。
